## 1. Что это за проект

- Сайт-инструкция для студентов к лабораторной работе
  **"Расчет наземных траекторий КА по TLE-параметрам (элементам) орбиты с созданием их ГИС-слоев"**.
- Автор - старший преподаватель кафедры механики и процессов управления инженерной
  академии РУДН (курсы по ГИС и ДЗЗ, основной инструмент - QGIS).
- Репозиторий: **RUDN-QGIS-ORBIT-L1**, публикация через GitHub Pages (Jekyll, тема Cayman).
- Шаблон-образец: сайт другой лабораторной работы **RUDN-QGIS-3D-L1** того же автора.
- Язык сайта и общения - русский.

Это **Часть 1** общей работы **"Расчет наземных траекторий КА и работа с ними
в геоинформационной системе QGIS"** из трех частей (трех лабораторных работ).
Каждая часть - отдельный сайт в едином стиле, части логически связаны:

- **L1 (этот сайт)** - расчет трасс скриптом, ГИС-слои точек и линейных сегментов
  в GeoJSON для МКС и TERRA, анимация пролета КА во времени в QGIS;
- **L2** - модуль QGIS "Globe Builder" (трассы на фоне земного шара в разных проекциях,
  в т.ч. азимутальной ортогональной и "Hammer & Eckert-Greifendorff"), обработка
  линейных сегментов модулем "Clip to Hemisphere", стили слоев, анимация на полусфере;
- **L3** - веб-карта с трассами через qgis2web, публикация на Netlify.

Короткие ссылки уже созданы: `bit.ly/RUDN-QGIS-ORBIT-L1`, `-L2`, `-L3`.
Сейчас работаем только над L1, но держим в уме связки с L2 и L3.

## 5. Python-скрипт лабораторной работы

Файл: **`TLE2GroundTracks_GeoJSON_2026-10-02.py`** (имя утверждено автором;
GitHub Pages чувствителен к регистру - в ссылках писать имя ровно так).

Что делает:

- получает TLE с Space-Track (библиотека `spacetrack`):
  - для сегодняшней и прошедших дат - из архива (класс `gp_history`) набор с эпохой,
    ближайшей к 12:00 UTC указанных суток, в окне `search_days` (по умолчанию 3) суток;
    печатает эпоху выбранного TLE и предупреждает, если она дальше 36 ч от полудня;
  - для будущих дат - самый свежий набор (класс `gp`), расчет с упреждением;
  - классы `tle` и `tle_latest` Space-Track больше не поддерживает - не использовать;
- рассчитывает положение КА (`pyorbital`) на сутки (0-1440 мин) с шагом `step_minutes`;
- пишет **GeoJSON точек** (по одному объекту на строку, как в экспорте QGIS,
  с членом `crs` = CRS84; файл .prj не нужен).

Атрибуты точек: `Point_ID`, `Orbit_Num` (номер витка), `Date_Time` (строка
`ГГГГ-ММ-ДД ЧЧ:ММ:СС`, **время UTC**), `Latitude`, `Longitude`, `Altitude` (км),
`Velocity` (км/с), `Sun_Zenith` (зенитный угол Солнца, град.), `Orbit_Incl` (наклонение, град.).

Вызовы в конце скрипта:

```python
create_orbital_track_geojson_for_day(25544, date(2026, 9, 32), 0.5, r'ISS_2026-09-32_30sec.geojson')
create_orbital_track_geojson_for_day(25994, date(2026, 9, 32), 0.5, r'TERRA_2026-09-32_30sec.geojson')
```

**День "32" оставлен НАМЕРЕННО** - это педагогический прием: студент обязан сам
вписать дату своего варианта. Не исправлять! В инструкции объяснить:

- без правки скрипт падает с `ValueError: day is out of range for month`
  (это ошибка выполнения, а не синтаксиса);
- менять **в двух местах** каждой строки: в `date(...)` и в имени выходного файла;
- месяц и день без ведущего нуля: `date(2026, 9, 6)`; запись `date(2026, 09, 06)`
  дает `SyntaxError`;
- шаг брать "ровный": 0.25, 0.5, 1, 2 мин (при неровных шагах вроде 0.1 округление
  секунд может дать 60 и ошибку);
- результат сохраняется в папку, где лежит скрипт (через `SCRIPT_DIR` на основе `__file__`),
  либо по полному пути, если он указан;
- логин и пароль Space-Track вписываются в свою копию скрипта; такой файл нельзя
  никуда выкладывать и пересылать;
- Space-Track ограничивает частоту запросов (библиотека сама держит < 30 запросов/мин),
  многократные запуски подряд всей группой могут вызвать временную блокировку.

**Запуск - только из командной строки и/или IDE, не из консоли Python в QGIS**
(решение автора). Поэтому `__file__` определен, запасной вариант не нужен.

**Варианты:** каждый студент рассчитывает оба КА (МКС 25544 и TERRA 25994) на одни сутки;
дата = [день - номер по списку группы] **сентября 2026**. Номера больше 30 преподаватель
назначает вручную - на сайте это не описывать.

**Пример во всей инструкции и на скриншотах - 27 сентября 2026**
(`ISS_2026-09-27_30sec.geojson`, `TERRA_2026-09-27_30sec.geojson`).

## 6. Python и библиотеки

- Минимум **Python 3.10** (этого требуют актуальные `spacetrack` и `pyorbital`;
  сам код скрипта нетребователен).
- Рекомендовать студентам **Python 3.12 или 3.13** (3.10 в октябре 2026 г. завершает
  жизненный цикл, самые свежие версии - не рекомендовать как основные).
- Проверенная автором связка: **Python 3.13, spacetrack 2.1.0, pyorbital 1.13.0, numpy 2.4.6**.
- Рядом со скриптом кладется `requirements.txt` (numpy не закрепляем - его подберет pip):

```
spacetrack==2.1.0
pyorbital==1.13.0
```

Для раздела установки:

- команда установки: `python -m pip install -r requirements.txt`
  (не голый `pip` - при нескольких Python на компьютере он может ставить "не туда");
- при ошибке доступа - ключ `--user` (учебные компьютеры без прав администратора);
- в установщике Python для Windows - галочка **"Add python.exe to PATH"** (показать скриншотом);
- pyorbital тянет scipy и pyproj - первая установка занимает несколько минут, не прерывать.

## 9. QGIS и ГИС-слои в Части 1

- Версия **QGIS 3.16.16** (как в 3D-L1: быстрая, компактная, стабильная).
  Автор проверил SQL-запрос и распознавание `Date_Time` также в QGIS 3.44 и 4.2.
- Проект в **EPSG:3857** (Веб-Меркатор), фон - OpenStreetMap.
- Стили слоев от студентов **не требуются** (по желанию); достаточно стилей QGIS по умолчанию.
  Настройка стилей - в Части 2.
- Компоновку (Макет) **не описываем**.

Построение линейных слоев (решение автора):

1. Точечные GeoJSON добавляются в новый проект.
2. Алгоритм **"Выполнить SQL-запрос"** (Инструменты анализа) - SQL-запрос из черновика
   в `index.md` строит **отдельные отрезки-сегменты**, каждому присваиваются атрибуты
   точки его начала. Результат - временный слой **"Вывод SQL"**; в нем поле `Date_Time`
   **строковое** (String) - это нормально.
3. **Объяснить с картинкой проблему горизонтальных линий** на антимеридиане ±180°
   (отрезки через всю карту) - **до** следующего алгоритма, чтобы было понятно, зачем он нужен.
4. Алгоритм **"Геодезическая линия, разделенная на 180° меридиане"** с сохранением
   в GeoJSON `<имя орбиты>_Segments.geojson`. В итоговом файле поле `Date_Time` уже
   определяется как QDateTime, размерности полей сохраняются как в скрипте.
5. Итог - **4 файла** (2 точечных + 2 `_Segments`) в папке `Calculated_Tracks`.

- Алгоритм **"Точки в контур"** (англ. "Points to path"; не "Точки в линию") - только
  упомянуть как альтернативу: строит линию (можно с группировкой по атрибуту), но
  с горизонтальными линиями на антимеридиане и без атрибутов по отрезкам.
- Последний пункт работы - **анимация пролета КА**: свойства точечного слоя,
  вкладка "Хронология" + панель управления временем QGIS, на фоне OpenStreetMap.
  Время в данных - UTC.
